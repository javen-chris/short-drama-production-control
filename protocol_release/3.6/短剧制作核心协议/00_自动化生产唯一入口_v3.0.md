> **协议版本：3.6**（2026-10-10 资产索引、证据恢复与流程可移植修订）
> **适用对象：** Hermes、Codex、以及任何能读取 Markdown 的 Agent。
> **适用范围：** D 盘全部短剧项目的脚本、镜头、故事本、视频、QA、剪辑交付。
> **优先级：** 用户最新明确指令 > 本文件 > 当前项目 `00_项目入口.md` > 当前项目状态与已确认文件 > 历史文件。

## 用户推荐指令

```text
项目=<项目ID或绝对路径>；段落=<明确EP/段号>；目标时长=<例如30秒>。
单条视频目标时长 ≤5 秒：直接通过对话推理，不启动本地生产协议。目标时长 >5 秒，或我明确说“按本地生产协议/建 RUN/过 Gate/完整留痕”时：脚本已经确认，请按短剧自动化生产协议自行决定镜头数量、生产单元、风险等级和生成路径。故事本图片默认关闭，除非我明确授权。只有我明确授权时才可使用 cash/企业通道；不得自行切换。读取本文件和当前 Gate 规则，再运行 Bootstrap。除真实阻断项外连续执行，不要每一步都让我说"继续"。
```

这条指令表示：脚本已确认；允许模型在不改剧情的前提下完成镜头拆分、风险分级、独立 QA、视频 Prompt，并按用户授权范围执行后续动作。故事本图片不在目标模式授权内。**默认路由是消费级会员NORMAL→coins API；“RunningHub API”不等于企业级API授权。cash/企业通道只有用户明确授权后才可使用。**

它不授权：改变已确认剧情、替换人物/场景 MASTER、失败后自动重试、换模型、增加时长、超预算、发布、删除或覆盖权威文件；**不授权Agent自行切换企业SHARED/CASH通道或自行选择计费通道。未取得用户明确cash授权时，必须使用NORMAL→coins；两者都无法满足时阻断。** 生图的处理见下文"生图授权模型"。

## 快速执行规则（协议 3.2）

### ≤5 秒视频的默认免协议路线

本次请求的**单条视频成片目标时长 ≤5 秒（含 5 秒）**时，默认不启动本地生产协议：不运行 Bootstrap，不建 RUN/合同/attestation，不走 G1–G6，不生成协议 QA 与运行轨迹。Agent 与用户通过对话确定方向，用推理直接给镜头建议或提示词草案。**只有用户明确要求“按本地生产协议 / 建 RUN / 走 Gate / 留完整轨迹”时才启用协议。**

该豁免仅取消本地流程性文书和 Gate；若用户要求实际付费生成，仍须遵守既有平台/费用授权边界，不得把免协议解释为提交授权。超过 5 秒或多条视频组成的序列仍按常规路由判断。

协议主流程为 **G0 接入 + G1–G6 六个生产 Gate**。项目接入和 RUN 恢复显示为 G0，但不增加审批门禁；G5.1 并入 G5；G6.1/G6.2 是 G6 内部检查项。新 RUN 在 G6-S12 查询授权任务至供应商终态、记录结果链接并报告后结束。自动下载、文件检查和成片 QA 不属于本地生产完成条件；用户明确要求成片分析时，另建独立分析任务。

目标模式且脚本已确认时，G1 与 G2 合并为一个“项目接入＋节拍＋镜头＋生产单元”交付包：Agent 一次整理、一次独立复核；只要不改变已确认剧情、台词、角色身份或用户锁定的镜头边界，就连续进入 G3，不逐项等待“继续”或重复请用户确认。常规模式仍由用户在该合并交付包后确认一次。

- **G1/G2 不重复审稿**：作者自查与一名独立 Reviewer 各执行一次；Reviewer 对同一候选输出一份合并结论，不再串行调用多个技能做相同核对。创作修订最多一轮；用户要求只拆解时不做创作修订。
- **G3 按变更复核**：资产 PASS 只绑定路径、角色和 SHA-256；三者未变时复用 QA，只核对本单元新增或变更资产。故事本/关键状态图默认关闭；单独请求某张角色状态参考图只授权该图及本单元用途，不转化为故事本授权。
- **G4 默认跳过**：故事本/关键状态图没有本单元明确授权时标为 `not_applicable`，不建任务、不读 G4 专项文件、不等审批、不计入阻塞项。
- **G5 必须调用对应视频模型的 Prompt Skill**：先确认本次生产模型，再调用该模型对应的 Prompt 写作 Skill；Skill 审计、Prompt 版本核验、参数/成本/资产清单和一次生成前 QA 都是 G5 内部要求，不再存在独立 G5.1 Gate。未执行对应 Skill 或证据缺失，G5 不通过。
- **G6 合并所有提交检查**：平台/算力参数、会话与上下文、资产绑定和提交报告均属于 G6 内部检查，不增加 Gate 数量。
- **G6-S12 默认只查询与报告**：按原 Task ID 查询至供应商终态，记录状态和输出链接并报告；不自动下载、不检查下载文件、不做成片 QA。用户明确要求这些后续动作时，作为独立任务处理。
- **协议读取证明按 RUN 复用**：同一 RUN、同一 manifest 指纹下，通用文件与通用挑战只证明一次；进入新 Gate 只补读新 Gate 文件并答其相关挑战。连续步骤合并一个证明。协议指纹变化才重做受影响证明。

**时间与停滞报告**：这是效率目标，不是删减必要检查的许可。简单任务参考主动处理时间：G1+G2 ≤7 分钟，G3（资产未变）≤3 分钟，G5（含对应模型 Prompt Skill 与生成前 QA）≤7 分钟；不含图像/视频外部生成、上传和供应商排队。G6-S12 的供应商等待单独计时，不作为 Agent 停滞。完成事件用 `at` 与 `elapsed_seconds` 记录；等待原因写入 `pending_decision`。10 分钟无新事件且无索引更新时间时，在 `pending_decision` 明示 `疑似停滞 STALLED`、最后有效事件和继续动作（索引枚举状态仍保留 `RUNNING`）。超出参考耗时不自动失败，保留已有产物并拆分耗时。

## 用户决定与防循环（协议 3.4）

所有 Gate 共用 `22_用户决策交互与版本防循环规则_v3.0.md`。只要修复会改变已确认剧情/台词、角色行为、动作结果、结尾、锁定镜头、资产身份或生成范围，必须先建立决策卡并在当前对话直接询问；QA FAIL/UNCERTAIN 不自动授予改动权。`current_owner=user` 只有在决策卡和用户可见问题均已交付后才有效。用户未答复前保持当前版本/RUN，不改稿、不重开 RUN、不重复 QA、不走相关下游。已授权范围内的格式和执行性去歧义可连续处理，不重复询问。

## Gate 与确认边界

| Gate | Agent 可以做什么 | 放行条件/终点 |
|---|---|---|
| G0 项目接入与 RUN 恢复 | 定位项目、集段、权威输入、有效产物与历史 RUN；创建或恢复 RUN | 当前状态明确；不增加审批门禁 |
| G1 权威脚本与节拍 | 整理已确认脚本、范围边界、对白/声音和节拍变化 | 输入及本次内容范围明确 |
| G2 镜头与生产单元 | 镜头调度、连续性、生产单元；G2-S04 一次合并独立复核 | 目标模式可与 G1 合并交付；复核结论有独立 QA 证据 |
| G3 资产映射与身份锁定 | 映射角色/场景/道具及身份资产，只复核新增或变化资产 | 当前单元资产绑定、身份和授权明确 |
| G4 可选故事本/关键状态图 | 仅在当前单元获授权时制作；否则 `not_applicable` | 未授权直接跳过，不构成阻塞 |
| G5 Prompt 编译、匹配模型 Skill 与生成前 QA | 调用所选模型 Prompt Skill；合并检查 Prompt、参数、成本、资产和授权 | 一次独立生成前 QA 通过；Prompt-only 到此结束 |
| G6 单平台适配、授权提交与状态查询 | S10 选择一个适配器并校验；S11 授权提交和留档；S12 查原任务并报告 | 成功终态与输出链接已核实并报告后结束 RUN；失败终止且不重试；未知结果记录异常 |

**关键解释：** "脚本通过"不等于生图；"故事本通过"不等于视频提交；"视频通过"不等于发布。任何付费、发布、删除、覆盖 MASTER 都需要对应动作的明确授权。

平台适配、提交前校验、授权提交、任务查询和结果链接记录均属于 G6。Prompt-only 合同将 G6 步骤标为 `not_applicable`。视频目标可在授权前完成本地 G6-S10 payload 编译与只读预检；G6-S11 之前必须在原 RUN 记录本次单次提交授权及证据哈希，之后才允许真实生成提交。RunningHub 为审核最终请求，可在已获该任务资产上传授权的范围内，于 S09 前上传已确认快照并冻结图片绑定；这只授权上传，不消费或授予视频生成额度。S10 正式记录校验同包，S11 提交时不得重新拉模板、拼节点或替换上传。提交失败不自动重试；已有任务恢复时只查询原 Task ID。记录工具绑定授权证据但不认证真人会话身份。

故事本授权、默认关闭状态、旧图隔离和未授权降级统一按 `核心自动化生产包/03_生产与资产规则_v3.0.md` 执行；Gate 适用条件以 `核心自动化生产包/02_任务路由与Gate_v3.0.md` 和 `skills/skill-chain.json` 为准。目标模式与风险等级本身不启用 G4/S07。生成后的分析仅按用户明确请求另行建立任务。

## 只允许因这些情况暂停

- 权威脚本无法定位或多个版本无法裁定；
- 所需人物、场景、道具 MASTER 缺失或冲突**（全自动目标模式下改为自动补齐：立即生成候选 → 独立 QA → 通过后使用；仅在 QA 连续 2 次不通过或成本超上限时才暂停）**；
- QA 为 `FAIL` 或 `UNCERTAIN`；
- **提交视频前的确认报告未通过内容校验（参考资产缺失、参数不全），或用户未确认，或授权范围为 `qa_only`**（见 `19_视频提交前确认报告与授权范围规则_v3.0.md`）——**用户已授权生成 ≠ 可以直接提交：内容不完整同样阻断**；
- RunningHub 路由、计费身份、原 Task ID 状态或余额变化未知；
- 默认不能证明 API `api_type == NORMAL` 且仅扣 `coins`；出现 `SHARED`、现金扣费、通道不明时，若没有用户明确cash授权，必须 `BLOCKED_CHANNEL_UNAUTHORIZED`，禁止继续；有明确cash授权时仍须先更新合同和确认报告，不得直接切换；
- 下一步将超出一次 720P 测试授权，或涉及重试、换模型、追加预算、发布、删除、覆盖。

任务卡、合同草案和资产映射尚未创建，不属于阻断项，模型应自动补齐。尾帧与故事本的授权和降级规则分别按 `核心自动化生产包/03_生产与资产规则_v3.0.md` 执行。

**生图授权模型（用户裁定 2026-09-20 晚）**：

- **全自动目标模式**：缺失身份 MASTER 的候选补齐权限按本节执行；故事本图片权限统一按 `核心自动化生产包/03_生产与资产规则_v3.0.md` 判断。
- **常规 Gate 流程**：缺资产时在 G3/G4 报告"建议生成 XX 资产"，等待用户明确授权后再执行。

目标模式下的硬性配套（不是授权门槛，是执行要求）：生成后必须独立 QA（PASS 才能当 MASTER）；每次必须落盘 `image_channel` 记录与成本；QA 连续 2 次不过或累计成本超 `budget_cny` → 暂停请示；不得覆盖已确认 MASTER（新版以候选形式生成，QA 通过并经用户确认后替换）。

模型固定 **GPT-Image-2**，不设例外品类；`seedream` / `banana` / `qwen-image` 等已全部停用。详见 `16_生图渠道规则_v3.0.md`。
