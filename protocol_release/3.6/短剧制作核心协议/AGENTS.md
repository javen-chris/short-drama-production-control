# AGENTS.md｜D盘短剧生产通用执行契约

> 协议版本：3.6 ｜ 最后更新：2026-10-10

## 读取顺序

**唯一来源：`00_自动化生产唯一入口_v3.0.md`**（含完整的读取顺序、按 Gate 补读清单与 Gate 表）。本文件不再重复维护文件清单，避免两处不同步。

本文件只补充执行约定：

1. 运行 `python <PROTOCOL_ROOT>/tools/short_drama_bootstrap.py --project <项目ID> --segment <明确EP/段号> --goal <阶段>`。常规任务无任务卡不得开始；用户明确"全自动/目标模式"时，自动创建任务卡、合同草案与资产映射后继续，禁止停在任务卡。
   例外：单条视频目标时长 ≤5 秒默认走对话推理，不启动本地生产协议或建 RUN；仅用户明确要求协议/RUN/Gate/完整留痕时才启用。付费生成授权边界仍有效。
2. 只按当前 Gate 补读原始细则（清单见唯一入口）。
3. 生成或检查 `TASK_CURRENT.md` 与 `production_contract.json`，再执行允许的动作。
4. G5 必须先选定视频模型并调用匹配的 Prompt Skill，再完成一次生成前独立 QA；G6-S12 查询原任务至供应商终态、记录输出链接并报告后结束 RUN，不自动下载或分析成片。
5. 目标模式且脚本已确认时，G1/G2 合并交付并一次独立复核；除剧情、台词、身份或授权范围需要裁定外，不在中间步骤停等。简单 5 秒单元按入口文件的效率目标记录耗时；10 分钟无事件标为 `STALLED`。
6. 新 RUN 只显示 G0-S01 至 G6-S12；恢复优先沿用原 RUN，资产索引、快照与哈希恢复按 `24_资产索引与RUN恢复规则_v1.md` 执行。旧 RUN 按创建时编号解释。

权威脚本、MASTER 或真实连续性输入缺失时报告阻断；任务卡、合同草案和资产映射缺失时由 Agent 自动创建，不得要求用户代写。

## 用户决定与防循环（协议 3.4）

- 任何实质改变已确认剧情/台词、角色行为、动作关系/结果、结尾、锁定镜头、资产身份、模型或生成范围的修复，必须依 `22_用户决策交互与版本防循环规则_v3.0.md` 形成决策卡，并在当前对话直接向用户提问。
- `current_owner=user` 或内部 `pending_decision` 不能代替用户可见提问；用户未答复时不得静默改稿、开新 RUN、重审或提交。
- 每版本一次合并 QA；同一问题轻微修复后最多一次定向复核。不得重置既用预算、提交次数或审批边界。

## 工作边界

- 用户决定：剧情、镜头、美术、人物身份、故事本、视频提示词、付费生成、发布。
- Agent 执行：资料核对、结构化草拟、文件索引、素材整理、抽帧、转码、独立 QA、状态和交接更新。
- Hermes 与 Codex 不共享对话历史。任何结论必须落进项目状态、确认单、交接或当前权威稿。

## 资产职责（不可混淆）

| 类型 | 唯一用途 |
|---|---|
| 人物 MASTER | 脸、发型、体型、服装、身份 |
| 场景 MASTER | 空间、材质、灯光、地理锚点 |
| 道具 MASTER | 形状、材质、尺寸、颜色 |
| 上一真实成片尾帧 | 下一镜起始动作、场景状态、道具位置 |
| 故事本 | 事件顺序、构图、镜头、站位；**不是身份来源** |

## 脚本与分镜强制读取

- 做脚本节拍检查、优化候选、镜头拆解或生产单元划分前，必须读取 `<PROTOCOL_ROOT>\09_脚本优化与分镜拆解规范_v3.0.md`。
- 已确认剧情只能提出候选改动，不能静默改写；镜头表确认前不能进入 G3/G4。

## 故事本强制读取与质量门槛

- 故事本图片、关键状态图与拼版默认关闭；未获用户对当前生产单元的明确授权时，S07 为 `not_applicable`，不得建立故事本任务单或 QA，不得阻断后续 Gate。
- 只有用户明确要求制作故事本/关键状态图，或明确授权当前生产单元使用故事本时，才进入 G4；进入后必须读取 `<PROTOCOL_ROOT>\08_故事本生产与QA规范_v3.0.md`，并执行其中逐格生成、独立 QA 与拼版规则。
- L0/L1/L2 和目标模式都不构成故事本授权；复杂镜头用镜头/动作拆解、强化 Prompt 禁止项和更严格视频 QA 处理。
- 正式故事本必须逐格生成、逐格 QA 后本地拼版；不得将整版直出作为正式生产故事本。
- 用户要求成片分析时，QA 必须与生成模型独立、完整播放并抽帧取证，逐项写 `PASS / FAIL / UNCERTAIN`。当前新流程无 G7/G8；下载与成片分析仅按用户后续请求另建任务。
- `UNCERTAIN` 不能称为通过；用户目视结论高于自动 QA。

## 文件规则

- 权威生产文件在项目 D盘目录；Obsidian 仅保留人读副本。
- `视频/` 只放成片；抽帧、联系表、QA 报告放 `qa/`；真实首尾帧/故事本放 `故事本&首尾帧/`。
- 被否决的产物进 `iterations/` 或 `_archive/`，不得覆盖 MASTER。
- 先审计再移动，最后才删除。删除仅限用户授权范围，必须保存 itemized manifest 并验证结果。
- 每一轮都更新状态：任务 ID、阶段、权威产物、批准内容、风险、下一步。
