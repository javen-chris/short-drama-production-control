# 平台路由卡｜跨窗口统一，不存密钥

> 密钥和 OAuth 只在本机凭证库 / `.env` / 已安装 CLI 中。此文件不记录、也不要求用户重复提供任何账号或密码。

| 路由ID | 用途 | 强制调用方式 | 禁止行为 | 失败处理 |
|---|---|---|---|---|
| `RUNNINGHUB_MEMBER_API_H3` | **默认日常视频生成** | 已核验的会员 `NORMAL→coins` Adapter；工作流 ID 从本机配置读取 | 不得自行切换 `SHARED→cash`；禁止从默认企业环境变量直接运行；不得盲重提 | 先查 `api_type` 与 coins/cash 前后余额；任一不符立即阻断 |
| `RUNNINGHUB_PERSONAL_H3` | 日常视频生成（用户明确指定个人网页端） | RunningHub 个人网页端；工作流 ID 从本机配置读取 | 不得擅自改走企业API；不得盲重提 | 只读核对个人端任务与费用；异常停在 `BLOCKED_CHANNEL_UNAUTHORIZED` |
| `LIBTV_MCP` | LibTV 工作区、画布、节点、素材、生成（**首选**） | LibTV Remote MCP 调用；先校验 MCP 连接与项目上下文 | 不用网页端手工操作替代；不假设项目 ID；不用 MCP 的可用性顶替 CLI 校验 | 记录 MCP 失败原因与错误码，**转 `LIBTV_CLI` 预检**，不得直接判整体阻断 |
| `LIBTV_CLI` | LibTV 工作区、画布、节点、素材、生成（MCP 不可用时的独立降级路径） | 官方 `libtv` CLI；先 `libtv --help` / 项目绑定再执行 | 不用网页端手工操作替代 CLI；不假设项目 ID；不用 CLI 的可用性顶替 MCP 校验 | 先 `libtv account` / `libtv project list` 只读诊断；报告 CLI 错误原文与错误码 |
| `XYQ_PIPPIT_CLI` | 小云雀短剧任务 | `pippit-tool-cli short-drama`；记录 thread_id/run_id，下载产物 | 不默认打开 Chrome 要重复登录 | 先只读查询已有会话/CLI 可用性；认证明确失效才提示 |

## 每次平台调用前的固定动作

1. 从任务卡读取 `platform_route`、已授权模型、预算、当前 Task ID。
2. 读取 `channel_class`；用户说个人端/网页端时固定为 `personal_web`，不得自行替换。
3. 若是 API，做只读通道预检：必须确认 `api_type=NORMAL`，并取得 coins/cash 前余额；不能读取到明确会员通道就停止。
4. 预检通过：按生产合同执行；提交后立即取得后余额并比对。
5. 预检失败：输出真实命令错误、受影响任务和恢复选项；不得让用户重讲“RunningHub 怎么用”。

## 规则

- 不把“浏览器能否登录”当成 API 可用性的判据。
- **`RUNNINGHUB_API_H3` 不再作为泛化路由名使用；默认路由必须是`RUNNINGHUB_MEMBER_API_H3`。不得用泛称API掩盖会员coins与企业cash的差异。**
- Agent 需要平台细节时，先加载对应本地 Skill：`runninghub` / `libtv-cli` / `xyq-short-drama-skill`；不从记忆编造命令。
- 一个段落提交后必须持久化：平台路由、工作流 ID、Task ID、输入、参数、费用、输出路径、最终状态。
- **LibTV 两条通道独立校验**：`LIBTV_MCP` 与 `LIBTV_CLI` 的认证状态不共享，
  **CLI Token 失效 ≠ MCP 阻断**。先预检 MCP，不可用再预检 CLI，两条都不可用才阻断。
  完整流程见 `20_G6生成提交与平台调用规则_v3.0.md`。
- G6 提交模式的两种取值（`AUTONOMOUS_SUBMIT` / `HUMAN_FINAL_CLICK`）与判定顺序，
  见 `20_G6生成提交与平台调用规则_v3.0.md` §二。\n
