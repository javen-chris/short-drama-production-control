# 24｜资产索引与 RUN 恢复规则

适用版本：协议 3.5 起。此文件定义资产索引和证据恢复的通用规则；步骤身份及协议范围仍以 `skills/skill-chain.json` 对应的步骤注册表为准。

## 一、系列库与单集项目

```text
<系列根>/
  系列入口文档
  资产库/
    asset_index.json
    人物/<角色ID>/<形态>/<服装>/<版本>/
    场景/<场景ID>/<版本>/
    道具/<道具ID>/<版本>/
  <每集独立项目>/
    项目入口文档
    脚本/  design/  场景资产/  物品资产/
    故事本&首尾帧/  提示词/  视频/  iterations/  _archive/
    workflow/
      project_state.json
      runs/<RUN-ID>.json
      asset_snapshots/<RUN-ID>/
      packets/<RUN-ID>/<版本>/
      qa_reports/<RUN-ID>/
      submission_receipts/
```

人物、场景、道具 MASTER 及其系列级权威索引放在系列资产库。单集独有或当集制作的场景、道具等保留在单集项目，并在项目入口登记权威路径。已有项目只补入口和索引，不批量搬迁文件。

## 二、资产索引

系列库使用 `asset_index.json`；控制台通过 `schemas/asset_registry.schema.json` 校验。每个资产记录至少应能确定：

- 稳定 `asset_id`、对象名称、职责类别、形态、服装、版本和确认状态；
- 权威源路径及原始文件 SHA-256；
- 参考职责（例如身份、场景空间、道具外形），禁止替代项；
- 用户确认依据、确认人/时间、QA 证据，以及追加式版本变化记录。

人物资产图是人物视频身份与外观的权威参考；场景 MASTER 管空间与地理锚点；道具 MASTER 管外形、尺寸与材质。故事本、关键状态图、真实尾帧、候选图和失败图各自保留来源与用途，不自动成为 MASTER。选材使用稳定 ID、职责、状态和哈希，不按相似文件名或视觉相似度自动替换。

索引是可查元数据，不内嵌媒体文件。单个 RUN 在用户确认使用资产后，可以在 `workflow/asset_snapshots/<RUN-ID>/` 保存不可变输入快照；快照只证明该 RUN 使用的输入，不取代或覆盖系列/项目 MASTER。

## 三、快照和恢复

启动时按已确认清单记录资产 ID、源路径、职责、版本、原始 SHA-256 和 RUN 快照路径。源文件改名、移动或变化不改变既有快照；后续新 RUN 是否采用新文件，按新确认处理。

快照缺失时，只能在当前已声明的项目/资产根目录按完整 SHA-256 精确查找。唯一候选方可恢复；多个相同副本按规范化相对路径排序后确定性选择，并记录候选列表、选择结果及复制前后哈希。不扫描全盘、不以相似图替代、不覆盖已存在但哈希不符的快照。

恢复优先使用原 RUN ID、合同、事件和 Task ID。控制台根据步骤事件、证据哈希、受影响文件哈希及当前适用协议哈希，定位第一个缺失或失效步骤；历史事件没有哈希时标记为“无法自动证明”，不推断它仍有效。恢复只追加检查记录并移动当前步骤指针，不删除事件、不重置预算、授权、QA 次数或提交消费次数。

如果已有供应商 Task ID，恢复只查询该 Task ID；若 RUN 等待用户或独立 QA，保持等待，不执行其依赖步骤。跨 RUN 只能复用满足产物、输入、模型参数、适用规则和 QA 路由哈希的内容产物及证明；授权、预算、Task ID 和提交次数不得跨 RUN 继承。

## 四、项目入口建议字段

```yaml
series_asset_index: "../资产库/asset_index.json"
project_asset_roots:
  scenes: "场景资产/"
  props: "物品资产/"
run_evidence_root: "workflow/"
```

实际路径由每集的项目入口文件声明；不得要求项目搬入仓库或 Obsidian。生产文件和媒体留在原项目目录。\n
