# 每段视频制作流程

> **3.6流程重整：** G0 接入与恢复 + G1–G6 生产；G6-S12 查询供应商任务至终态并报告结果链接后结束 RUN，不自动下载或做成片 QA。单条视频 ≤5 秒默认免协议；G5 必须调用对应模型 Prompt Skill。RUN 恢复与资产索引按 `24_资产索引与RUN恢复规则_v1.md` 执行。

> 协议版本：3.6 ｜ 最后更新：2026-10-10

> **2分钟不是一次生成任务。** 先按剧情/场景/动作因果拆成多个 5–12 秒生产单元；每个单元完整走 Gate，剪辑阶段才合成 2 分钟。

## G0：项目接入、任务路由与 RUN 创建/恢复

G0-S01 定位项目与权威材料，识别集/段、当前有效产物、历史 RUN 和恢复位置。G0 是接入与恢复，不增加审批门禁；历史 RUN 沿原编号与证据续接。

## G1：权威脚本与节拍整理

项目接入、RUN 创建与恢复由 G0-S01 完成，不增加审批门禁。G1-S02 确认当前集/段权威脚本、项目状态、最新交接、用户确认边界；连续镜头需要时定位上一有效参考。然后形成/确认秒表脚本与节拍链。

用户看的是一张表，必须包含：

| 时间 | 画面/场景 | 动作/表演 | 台词/声音 | 连续性 |
|---|---|---|---|---|

每 3–5 秒至少有一个可见变化。复杂动作、多人对白、跨场景必须拆段，不能硬塞。

## G2：镜头与生产单元

G2-S03 对每个生产单元明确镜头目的、景别、机位、人物数量、屏幕左右、场景锚点、道具、起始状态和结束状态。G2-S04 对脚本节拍与镜头做一次合并独立复核。目标模式可将 G1/G2 结果合并交付；仍须留存复核证据。禁止全段同机位重复。

## G3：资产映射与身份锁定

每个画面出现的角色、场景、关键道具，列出实际路径与职责。人物身份必须用单人身份图，不能拿五视图拼版、故事本或视频截图替代。

## G4：可选故事本/关键状态图

故事本/关键状态图默认关闭。只有用户明确要求或授权当前单元制作时才进入 G4，并逐格确认和 QA；未授权则跳过，不得成为后续生产的门禁。

## G5：Prompt 编译、匹配模型 Skill 与生成前 QA

先确认本次实际使用的视频模型，再调用该模型对应的 Prompt 写作 Skill（例如 Seedance 使用 Seedance Prompt Skill，H3 使用 H3 Prompt Writing Skill）。不得以通用 Prompt 编写代替模型 Skill。

Prompt 必须包含：参考图职责、按秒时间轴、唯一主动作、镜头、台词与声音、明确禁止项、模型/比例/时长/成本。记录 Skill 名称/版本/调用证据、Prompt ID/版本和输入哈希；Prompt 修改后对新版本重新调用对应 Skill。原 G5.1 Skill 审计要求并入 G5，不形成独立 Gate。完成一次最小充分等级的独立生成前 QA；提供完整正文或明确文件路径。

## G6：授权提交与任务查询

G6-S10 按合同选择一个平台并完成提交前校验；G6-S11 仅在本次授权后提交一次并记录真实任务 ID；G6-S12 只查询原任务，合理间隔报告处理中状态。供应商成功终态经核实且输出链接已记录并报告后结束 RUN；失败不自动重试，状态或结果无法核实则记录异常并停下。此 RUN 不自动下载、检查文件或做成片 QA。

> **G6 完整规则已单独立项**：提交模式（AUTONOMOUS_SUBMIT / HUMAN_FINAL_CLICK）、
> LibTV 双通道独立校验、认证错误码与停止规则、八步节点流程、幂等与超时重提、
> G6 失败异常队列 —— 全部见 **`20_G6生成提交与平台调用规则_v3.0.md`**。
> 下列算力与上下文要求是 G6 内部检查，不是额外 Gate。提交流程以 `20_G6生成提交与平台调用规则_v3.0.md` 为准。

### G6 内部检查 A：平台算力档位与 MP 选择

**GPU实例升级规则**：

- H3等视频工作流在提交前按模型与任务复杂度选择实例档位；配置只在本次提交前确定并纳入授权与预算，不得在提交失败后自动换档重跑。
- 升Plus前必须：①确认云端旧任务已终态（FAILED/已取消），杜绝双任务并行；②记录新旧两个Task ID与各自费用；③失败任务确认零扣费后再提交Plus。
- 默认计费通道：消费级会员key（`api_type=NORMAL`→`coins`）。提交前必须保存通道预检证据：`api_type`、提交前后 `coins`/`cash` 余额快照；缺任一项不得提交。只有用户明确授权cash/企业通道，并更新合同与确认报告后，才允许 `SHARED→cash`；不得自行切换。若用户指定个人网页端，则使用网页端，不得改走API。

**megapixels档位表（16:9）**：

| MP | 分辨率 | 何时使用 |
|---|---|---|
| 0.4-0.6 | 864×480-1056×608 | 24G默认档；快速测试闭环、构图验证、废片风险高的首跑 |
| 0.9 | 1280×704 | 24G上的日常成片档；≤6秒短视频或7-8秒中负载 |
| 1.2 | 1504×832 | **24G安全上限档**；7-10秒正式成片在24G的标准选择 |
| 1.4 | 1664×928 | 24G临界档：仅≤8秒可用；超8秒大概率OOM失败 |
| 1.8 | 1824×1024 | **必须Plus 48G**；8-10秒正式成片高清档 |
| 2.0 | 1920×1088 | **必须Plus 48G**；≤6秒顶格清唽档（用户自行超分）；8-15秒在Plus上可用但等待更长 |

**决策顺序**：提交前根据上表选定 MP 与实例档位并写入确认报告。供应商失败后记录失败状态、Task ID 和费用回执并停止；调整参数、通道或再次提交须由用户另行授权。

### G6 内部检查 B：窗口上下文健康与轮换机制

> 目的：短剧自动化生产窗口在长任务中上下文累积过大，可能导致视觉 QA 响应变慢。本机制让**任何窗口**在开工前和过程中检测、记录并适时交接，不在协议文本中发布个人使用量或生产任务耗时。

**触发逻辑（谁、何时执行）**：

- **适用范围：所有执行短剧自动化生产的窗口**（Hermes/Codex/任何Agent），不限于某个聊天。
- **强制检测点（Agent必须运行检测工具）**：
  1. 按本地协议启动 G1 时；
  2. 每完成一个生产单元（一段视频/一批故事本/一次付费提交）后；
  3. 任何vision分析响应明显变慢（>30秒）时立即检测。
- **检测命令**：

```bash
python <PROTOCOL_ROOT>/tools/window_context_check.py
```

- 工具读取Hermes `state.db` 最新会话的**真实API计费token**（非估算），返回 `OK / WARN / ROTATE` 三态（退出码0/1/2）。

**裁决与动作**：

| 判定 | 阈值（默认） | 必须执行 |
|---|---|---|
| OK | 低于维护者本机配置的提醒阈值 | 继续生产 |
| WARN | 达到维护者本机配置的提醒阈值 | 完成当前生产单元后记录交接建议 |
| ROTATE | 达到维护者本机配置的停止阈值 | 按本机安全规则停止新提交并记录交接 |

- 空闲超过30分钟的会话视为已废弃，检测工具自动忽略（防止误报旧窗口）。
- 具体阈值及本机工具路径由维护者本机配置管理，不纳入公共发行副本。

**交接协议（ROTATE/WARN时）**：

1. 按该项目既有铁律写 `FINAL_HANDOFF_*.md`（唯一续接依据：任务ID、当前Gate、已完成/进行中、下一步、风险）。
2. HANDOFF写入项目 `workflow/` 目录；Obsidian同步按既有规则。
3. 向用户报告检测数据（token数）+ 建议指令「新窗口打开后读取 <HANDOFF路径> 续接」。
4. 新窗口按 `00_自动化生产唯一入口_v3.0.md` 的读取顺序开工；Hermes与新窗不共享聊天记忆，只靠文件续接。
5. **禁止**在ROTATE窗口继续提交付费任务、跑长vision分析——上下文过大不仅慢，还会增加生成提示词与参数出错风险。

**与原生压缩的关系**：Hermes双层压缩（50%/85%）只保证API不因超长而失败，不解决响应变慢与上下文质量衰减——本机制是生产质量门禁，不是系统故障修复。

## G6-S12：生成任务查询与结果报告

提交后按原 Task ID 查询直至供应商成功/失败终态，告知用户生产进度和结果；成功时记录供应商返回的视频链接和必要任务信息。不得自动下载、盲目重提或重复扣费。下载、转码及文件 QA 由后续独立请求触发。

本地生产 RUN 在 G6-S12 报告供应商终态与结果链接后结束。成片画面/声音 QA 不属于该 RUN；只有用户明确要求成片分析时，才另建独立任务并按时码提供证据。

剪辑、字幕、封面与发布不属于本地生产协议 Gate；用户另行要求时作为独立任务处理，并遵守对应授权边界。\n
