# 生图渠道与资产安全规则（去敏发行副本）

适用模型：GPT-Image-2。此文件发布授权边界和一般接口职责；具体供应商 ID、当前报价、账户余额、工具路径和生产测试数据保留在本机适配器与权威协议中。

## 通道选择

1. 默认使用已配置的本机订阅通道。
2. RunningHub 仅作为本次合同与用户授权明确允许时使用的付费兜底。授权前核验当前供应商、账号通道、准确 payload、资产清单、报价和预算余额。
   本机常用的通道标签为 `gpt_image2_runninghub_workflow`；该标签本身不构成授权。
3. 模型或平台不可用时停止并报告，不擅自换模型、提高规格、切换付费通道或重复提交。
4. 供应商应用 ID 和节点字段由本机适配器按当前任务读取。公共发行副本不保存真实 ID 或账号配置。

## 资产与请求绑定

- 只使用已批准资产索引中按职责、身份和 SHA-256 锁定的输入；不得用文件名或视觉相似度猜测替代 MASTER。
- 用户确认的输入可按该 RUN 保存不可变快照。快照不取代 MASTER，不覆盖权威源文件。
- 提交前将模型、提示词、分辨率、比例、参考图职责、资产哈希、当前供应商报价、预算和授权绑定到同一合同。
- 提交失败、超时或供应商状态不明时保留已消费次数并暂停。任何再次提交必须由用户另行授权。

## 费用、证据与保密

- 在本机合同中记录当次供应商报价与预算上限；缺报价、超预算或费用状态不明时停止。不得将历史费用或账号余额作为当前报价。
- 轨迹只记录请求身份、授权依据、真实任务 ID、状态、耗时和错误。API key、认证头、原始凭据以及用户私密信息不得写入轨迹或代码。
- QA 内容结论与供应商执行事实分开记录。模型名是路由声明，不证明真实会话或服务端身份。

故事本、关键状态图和拼版默认关闭；是否制作以当前生产单元的明确授权为准。详细资产目录、源文件、RUN 快照和哈希恢复规则见 `24_资产索引与RUN恢复规则_v1.md`。\n
