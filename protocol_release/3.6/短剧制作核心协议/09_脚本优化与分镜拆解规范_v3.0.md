# 脚本优化与分镜拆解规范

> 协议版本：3.0 ｜ 最后更新：2026-09-28

> **状态：** `ACTIVE_METHOD_LIBRARY`。用于强化已确定脚本的节拍、钩子、反转、镜头拆解与机位覆盖；不得擅自改变已确认剧情、人物关系、世界观或平台权限。

## 一、脚本优化：先检查节拍，再拆镜头

实质改动边界、决策卡字段、当前对话提问要求和 QA 防循环统一遵循 `22_用户决策交互与版本防循环规则_v3.0.md`。Reviewer 只提供证据与影响分类，不能以 FAIL/UNCERTAIN 替用户选择改法；修复若改变已批准的动作、台词、接触关系、结尾、镜头锁定或生产范围，先停并在当前对话提交决策卡。

### 创作判断与有限修订流程

对用户交来的已确认脚本，先判断本次任务是“只拆解”还是“允许提出创作候选”。只拆解时不得改故事；允许优化时，也只能另存候选稿，原稿和确认状态不变。不得把个人审美偏好伪装成硬性失败。

按下列五项逐项给出 `PASS / REVISE / UNCERTAIN`，每项都引用具体时间点、台词或镜头作为依据：

| 检查项 | 可执行判断 | `REVISE` 的典型信号 |
|---|---|---|
| 开场钩子 | 0–3 秒内观众能看见异常、威胁、强结果、关系冲突、明确目标或信息缺口之一；能说清“我为什么想继续看” | 只有走路、空镜、寒暄、无目标摆姿势；看完开场仍不知道发生了什么或要关注什么 |
| 节拍因果 | 每个节拍都改变信息、行动、关系、空间、风险或目标状态；后一拍由前一拍引出，而非只并列事件 | 删除一拍后剧情毫无影响；行动没有可见结果；目标或阻碍只靠解释，没有画面证据 |
| 爆点/反转 | 先有可追溯的铺垫；揭示后至少改变目标、风险、关系或信息真相之一，并能改变角色下一步行动 | 仅靠音效、特效、表情或镜头推近制造“很大”的感觉；揭示与前文无因果，或不改变后续行动 |
| 镜头表达 | 景别、角度、运动和观众注意点服务于本镜信息/情绪/动作目的；相邻镜头有可解释的覆盖变化 | 连续镜头机位相同且信息重复；关键动作看不清；镜头运动增加复杂度却没有叙事收益 |
| 视频生成可执行性 | 单镜有一个主视觉因果、明确主体/动作/结束状态；时长、空间、人物、接触和说话权适合目标模型稳定表达 | 一个生成单元塞入多段因果、多人抢话、高风险接触或多个空间变化；动作起止/关键状态无法描述或验证 |

“每 3–5 秒至少一次可见变化”是节奏检查的警戒线，不要求机械切镜或持续刺激。安静、停顿和留白可以保留，但必须承担蓄势、反应、情绪或信息功能。镜头多样性也不是随机换景别；优先保证信息清楚、因果可见和模型可执行。

流程固定为：①作者先自查并定位问题；②将同一版本的问题合并，最多进行一轮集中候选修订；③用完整检查表复查候选稿；④交给一名独立 Reviewer 对当前最终候选一次性复核并列证据。自查不能给自己签独立 QA PASS。不得把拆解、Reviewer、连续性技能串成多轮重复审查同一内容；Reviewer 在同一份报告中覆盖脚本节拍、镜头与空间连续性。若一轮修订后仍有 `REVISE`，或关键判断为 `UNCERTAIN`，停止下游步骤并给出最多 3 个阻塞点及需要用户裁定的选项；不得无限改稿或反复调用完整 QA。

候选稿须标出来源版本、改动位置、改动前后和对应检查项。用户未确认前，候选稿不得替代权威脚本，也不得进入后续资产、故事本或视频 Prompt 阶段。用户明确要求“只检查”时，只报告问题和建议，不改写任何稿件。

### 1. 开场钩子

每个视频单元前 0–3 秒必须至少出现一种：异常、威胁、强结果、关系冲突、明确目标、信息缺口。禁止先走路、寒暄、空镜或无目标摆姿势。

### 2. 节拍链

每段至少写出：

```text
钩子 → 目标 → 阻碍 → 行动 → 结果/反转 → 未解决问题
```

每 3–5 秒至少一次可见变化：信息、行动、人物关系、空间、风险或目标状态发生变化。

### 3. 反转

反转必须改变观众对“目标、风险、人物关系、信息真相”至少一项的判断；不能只是表情变严肃、镜头变近或特效变大。

### 4. 台词

台词只服务当下节拍：一条新信息一句只给一个；问有来源、答针对问；说话权按镜头拆开。不能靠对白解释画面已经能表现的内容。

### 4.1 自查结论的使用

`PASS` 表示按本规范检查未发现阻断项，不代表用户已确认剧本，也不代表独立 QA、生成授权或成片通过。`REVISE` 表示先完成有限候选修订；`UNCERTAIN` 表示缺少权威输入或需要用户选择，禁止猜测后继续。

## 二、分镜拆解：一镜一视觉因果

### 5. 一镜一件事

每镜只承担一个明确的视觉因果：谁在何处，为何做什么，造成什么新状态。目标、空间、人物关系、镜头任务、说话权或动作结果改变时，通常应拆镜。

### 6. 动作拆法

高风险动作按：`起势 → 接触 / 受阻 → 结果` 分拆。禁止把追逐、躲避、抢夺、打斗、变形和结果强塞进一个生成单元。

### 7. 镜头目的与覆盖

| 目的 | 优先镜头 |
|---|---|
| 建立空间、人数、危险规模 | 大全景 / 全景 |
| 人物关系、走位、动作 | 中景 / 双人中景 |
| 反应、决定、说话权 | 中近景 / 近景 / 反打 |
| 关键道具、手部接触、信息落点 | 特写 |
| 压迫、权力、空间规模 | 仰拍 / 俯拍 / 越肩 |

禁止连续多镜头无意义使用同机位。每一镜必须标明“观众此刻先看谁”。

### 8. 轴线与空间

确立人物左右位置和视线方向后，不得无理由跨越 180° 轴线；若必须翻轴，先用建立镜头或明显的移动镜头重建空间。

### 9. 镜头与生产单元不同

分镜是叙事覆盖；视频生产单元是模型可稳定生成的连续片段。只有同一空间、同一服装、低风险连续动作、单一说话权的 2–12 秒镜头，才可合为一个生产单元。跨场景、多人抢话、强接触、变装、新角色首次出现、关键道具变化必须拆开。

### 10. 输出物

脚本优化或分镜任务必须产出一份合并的 `G1-G2_节拍镜头与生产单元.md`，至少包含：权威脚本引用与哈希、逐秒节拍、镜头目的/景别/机位/动作/起终状态、轴线与连续性、生产单元依赖图摘要、待用户决定项、作者自查和独立 Reviewer 结论。无需为同一候选另行生成重复确认稿。

生产单元依赖图可以作为同文件内 JSON 区块或单独机器文件保存，但不得重复复制同一审核结论。

## 三、模型专用 Prompt 调用规则

### Seedance

使用已安装的 `seedance-*` 系列 Skill，尤其是 `seedance-prompt`、`seedance-camera`、`seedance-motion`、`seedance-characters`、`seedance-sequence`、`seedance-continuation` 与 `seedance-antislop`。先由本规范锁节拍和镜头，再转模型语法；模型 Skill 无权改写脚本或资产映射。

### MiniMax H3 / RunningHub

使用 `aigc-storyboard-video-pipeline`、`aigc-multimodel-workflow`、`runninghub-task-discipline` 与 `runninghub-billing`。工作流 ID、模型、时长、参考图槽、费用和提交权限以本机适配器及当前生产合同/任务卡为准。H3 Prompt 必须按秒列唯一主动作、唯一说话人、参考图职责、镜头、声音、禁止项；不得把故事本当人物身份参考。

## 四、不可越过的边界

- 优化建议不覆盖用户确认脚本；要改剧情必须新建候选稿等待确认。
- 本规范只产生分镜、节拍和 Prompt 草稿；不授权故事本、视频提交、付费或发布。
- 连续性始终使用人物/场景/道具 MASTER 与真实尾帧的职责分离规则。\n
