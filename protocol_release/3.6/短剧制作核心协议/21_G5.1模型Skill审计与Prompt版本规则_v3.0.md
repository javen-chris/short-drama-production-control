# 21｜G5 对应模型 Prompt Skill 与版本核验规则 v3.0

> **协议版本：3.4** ｜ 立项日期：2026-09-24 ｜ 更新：2026-10-12
> （文件名保持 `_v3.0` 后缀 —— `VERSION.md` 命名规范：次版本升级不改文件名。）

> **定位：本文件定义 G5 内部的强制模型 Skill 检查，不是独立 Gate。**
> 生产提示词前必须先确认实际视频模型，并调用与该模型匹配的 Prompt 写作 Skill；不能用通用 Prompt 编写代替模型 Skill。Skill 证据与 Prompt 版本核验均计入 G5。
>
> 与 `20_G6生成提交与平台调用规则` 的分工：
> **20 管"资产对不对、钱怎么花"，21 管"提示词能不能用"。两道都要过才允许建节点。**

## 一、G5 内部的模型 Prompt Skill 步骤

```
G5：确认模型 → 调用对应 Prompt Skill → 记录 Prompt/Skill 版本与证据 → 生成前 QA → G6
```

**对应模型 Prompt Skill 未实际运行、证据缺失或未通过时，G5 不通过，禁止：**

- 创建视频节点
- 更新视频 Prompt
- 连接参考资产
- 生成提交报告
- 点击生成（无论 Agent 代点还是人工点击）

## 二、模型 Skill 审计证据（每个视频生产单元一份）

先以当前合同中的 `unit_id` / `model` / `model_version` 和当前 Prompt 的 `mode` 选择对应模型 Skill。允许的模型别名由审计器显式登记；未登记、冲突或合同不匹配一律阻断，不得猜测放行。

必需 Prompt Skill 映射：

| 合同模型 | 必需 Skill |
|---|---|
| `rh_h3` / H3 | `h3-prompt-writing` |
| `seedance_2.5` / Seedance 2.5 | `seedance-shot-design` |
| `seedance_2.0` / Seedance 2.0 | `seedance-20`（路由）及 `seedance-prompt`（Prompt 编写） |

模式必须为当前模型 Skill 支持的模式：H3 为 `T2VA` / `I2VA` / `FL2VA` / `L2VA` / `Ref2VA`；Seedance 2.0 为 `T2V` / `I2V` / `V2V` / `R2V` / `FLF2V`；Seedance 2.5 使用已登记的生成、长视频、续写、编辑、视角修改、音频、绿幕、白模、转场或多格故事板模式，以及其明确支持的 `T2V` / `I2V` / `V2V` / `R2V` / `FLF2V`。不得将一种模型模式推断成另一种模型模式。

只记录本模型实际适用并执行的 Skills；不得用其他模型的 Skill 清单冒充。模型 Skill 不存在或不可调用时，写明原因并阻断。

落盘路径：

```
workflow/skill_audits/<unit_id>_skill_audit.json     ← 机器可校验
workflow/skill_audits/<unit_id>_skill_audit.md       ← 人读（推荐）
```

JSON 必须绑定当前合同、生产单元、Prompt 内容和输入。`contract_path`、`prompt_path`、`input_hashes` 均为项目根目录内的相对路径；Prompt 可以是文本或 JSON，均按文件内容计算 SHA-256；JSON Prompt 另须在内容中匹配 `unit_id` 与 `mode`。每项 Skill 的 `evidence` 必须是项目内可读取 JSON 证据文件的相对路径及其 SHA-256。证据记录需匹配 `unit_id`、`skill_id`、合同模型/版本、模式、`prompt_sha256`、完整 `input_hashes`，并声明 `status: PASS`。

示例字段（哈希为占位，必须从当前文件计算）：

```json
{
  "unit_id": "EXAMPLE-UNIT-01",
  "model": "Seedance 2.5",
  "model_version": "2.5",
  "mode": "I2V",
  "contract_path": "workflow/submission_reports/EXAMPLE-UNIT-01.json",
  "prompt_path": "prompts/EXAMPLE-UNIT-01.json",
  "prompt_sha256": "<当前 Prompt 文件的 64 位 SHA-256>",
  "input_hashes": {"script/confirmed.md": "<当前输入文件的 64 位 SHA-256>"},
  "prompt_id": "EXAMPLE-PROMPT-v1",
  "prompt_version": "v2",
  "skill_audit_id": "EXAMPLE-SKILL-AUDIT-v1",
  "skills": [
    {"id": "seedance-shot-design", "version": "local", "status": "PASS", "evidence": {"path": "workflow/skill_audits/evidence/EXAMPLE-UNIT-01-seedance-shot-design.json", "sha256": "<证据文件的 64 位 SHA-256>"}}
  ],
  "overall": "PASS"
}
```

证据文件是可核对的执行记录，不是身份认证或防篡改签名。校验器不声称仅凭一段文本能证明模型/Skill 身份；不得伪造签名字段。独立内容 QA 仍按 QA 规则执行，Skill 读取/运行记录不能替代 QA PASS。

**整体判定（硬性）**：必须同时满足无 `errors`、无阻断 `codes`、`overall` 精确为 `PASS`、Skills 非空、所有状态精确为 `PASS`、模型路由正确、合同/模式匹配、Prompt 内容哈希与输入哈希有效、每项证据可读且绑定当前生产单元。非法或缺失状态、任何非 PASS 状态均为 `SKILL_GATE_BLOCKED`。

| 任一适用 skill 的 status | overall |
|---|---|
| 全部 `PASS` | `PASS` |
| 出现任一 `FAIL` / `UNCERTAIN` / `NOT_RUN`、非法或缺失状态 | **`SKILL_GATE_BLOCKED`** |
| `skills` 数组为空 | **`SKILL_GATE_BLOCKED`**（等同于没跑） |

**不得**把 `NOT_RUN` 当成"待办"放过；**不得**以"这次先跳过、下次补"为由放行。

## 三、Prompt 必须携带三件套

每个视频 Prompt 必须写明：

```
prompt_id        例：EXAMPLE-PROMPT-v1
prompt_version   例：v2
skill_audit_id   例：EXAMPLE-SKILL-AUDIT-v1
```

**改 Prompt 就要重来**（哪怕只改一个句子）：

1. `prompt_version` 递增（v2 → v3）
2. 重跑全部 Skill
3. 重新生成 Skill 审计报告（新 `skill_audit_id`）
4. **旧节点标记为过期**（`stale`，禁止直接生成）

**要防的事**：审计的是 Prompt v1、节点实际用的是 Prompt v2。

## 四、节点创建器硬校验

创建视频节点的接口必须做以下检查，**任一不过即阻断**：

```python
if (not skill_gate.ok or skill_gate.overall != "PASS"
        or skill_gate.errors or skill_gate.codes):
    BLOCKED_SKILL_NOT_PASSED

# 独立内容 QA 必须单独 PASS；Skill 执行记录不能代替它
if independent_content_qa.overall != "PASS":
    BLOCKED_INDEPENDENT_QA_NOT_PASSED

# 版本/模型/模式三者必须与审计一致；缺少值也阻断
skill_audit.prompt_version == node.prompt_version
skill_audit.model          == node.model
skill_audit.mode           == node.modeType
# 缺失或不一致 → PROMPT_VERSION_MISMATCH，阻断
```

## 五、视频 Prompt 最低结构检查（少一项不得报 PASS）

对 Seedance 类视频 Prompt，至少必须检查以下 **15 项**：

| # | 检查项 | # | 检查项 |
|---|---|---|---|
| 1 | 模式（I2V / R2V / mixed2video） | 9 | 角色动作分配 |
| 2 | 参考图职责映射 | 10 | 物理动作结果 |
| 3 | 一个主意图 | 11 | 声音 |
| 4 | 主体标签 | 12 | 保持项 |
| 5 | 唯一主动作 | 13 | 禁止项 |
| 6 | 起始状态 | 14 | 资产职责与 Prompt 引用一致 |
| 7 | 时间轴 | 15 | 时长/比例与合同一致 |
| 8 | 结束状态 | | |

**缺任何适用于所选模型的必需项 → 该 Prompt 不得报 PASS，不得进入 G6。** Seedance 的 15 项表只适用于 Seedance；其他模型按对应 Prompt Skill 与合同参数检查，不将 Seedance 专属字段生搬硬套。

## 六、错误码（硬阻断，不降级、不重试）

| 错误码 | 触发 | 处理 |
|---|---|---|
| `SKILL_NOT_RUN` | `skills` 为空或存在 `NOT_RUN` | **不允许自动降级，不允许"先建节点再补 Skill"**，留在 G5 |
| `SKILL_STATUS_INVALID` | Skill 状态缺失或不在允许枚举中 | 阻断并修复审计记录 |
| `SKILL_GATE_FAIL` | 存在 `FAIL` | 停止，按 Skill 报告修正 Prompt，重跑对应模型 Skill |
| `SKILL_EVIDENCE_MISSING` / `SKILL_EVIDENCE_INVALID` | PASS 证据缺失、不可读、哈希错误或未绑定当前输入 | 停止；**无效证据的 PASS 视为未跑** |
| `SKILL_MODEL_UNKNOWN` / `SKILL_MODEL_MISMATCH` | 模型/版本/必需 Skill 不明、合同不一致或混入其他模型专用 Skill | 不猜测模型路线，停在当前 RUN 等待处理 |
| `PROMPT_CONTENT_MISMATCH` / `SKILL_INPUT_MISMATCH` | Prompt 哈希、单元、模式或相关输入哈希不匹配 | 重新对当前内容审计；改版本名不能绕过 |
| `INDEPENDENT_QA_REQUIRED` | Skill 执行通过，但独立内容 QA 未通过或缺失 | 保持 G5 未完成；不以 Skill 运行记录代替 QA |
| `PROMPT_VERSION_MISMATCH` | 审计与节点的版本/模型/模式不一致 | 停止，重新审计或回滚节点 Prompt |
| `ASSET_GATE_NOT_READY` | 资产门禁（`20` §四）未过 | 停止，先补资产绑定 |
| `PLATFORM_NODE_CREATED_BUT_NOT_PRODUCTION_READY` | 节点建了但生产就绪未达标 | 停止，禁止生成（见 §七） |

## 七、区分"技术节点成功"与"生产节点合格"

节点必须**同时**记录两个状态：

```json
{"platform_node_status": "CREATED", "production_readiness": "FAIL"}
```

`platform_node_status` 只说明平台建了这个节点；
`production_readiness` 才说明它能不能用来生产。

**`PRODUCTION_READY` 必须同时满足**：G5 对应模型 Prompt Skill 通过 + 独立内容 QA 通过 + 资产门禁通过 + 版本一致 + 所选模型适用的结构检查全通过。

**禁止**因为 MCP 返回 `operation completed` 就把节点标成可生成——那只是 `CREATED`。

G6-S11 进入任一平台提交适配器前，控制台必须按当前 RUN `task_id` 重新读取并核验该生产单元的 Skill 审计；缺失、不可读或非 PASS 则暂停 RUN，不调用提交适配器。恢复时沿用原 RUN，不重置预算、授权、审查和提交次数。历史 RUN/证据保留原样，不因新校验要求回写。

## 九、禁止清单

- 禁止在 G5 对应 Prompt Skill 没有 `PASS` 时创建/更新任何视频节点与 Prompt。
- 禁止把 `NOT_RUN` / `UNCERTAIN` 当作通过。
- 禁止无证据的 PASS（等于没跑）。
- 禁止改了 Prompt 不递增版本、不重跑 Skill。
- 禁止拿 Prompt v1 的审计去放行 Prompt v2。
- 禁止把"平台建节点成功"当作"可以生成"。
- 禁止先建节点再补 Skill。\n
