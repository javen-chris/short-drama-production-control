# 目标模式｜自动建卡与连续执行规则

> 协议版本：3.0 ｜ 最后更新：2026-09-20

> **状态：** `ACTIVE_CORE_RULE`
> **目的：** 用户已经明确下达“全自动/目标模式 + 项目 + 段落 + 可执行目标”时，Agent 不能拿缺少任务卡、合同草稿、资产映射或旧任务 FAIL 当理由直接判定“不可实现”。

## 一、目标模式的输入

### 时长优先路由

本次请求为单条视频成片且目标时长不超过 5 秒时，默认走对话推理轻路线，不进入目标模式的 Bootstrap、RUN/合同、G1–G7、attestation 或轨迹流程。用户明确要求使用本地协议、建 RUN、过 Gate 或完整留痕时，才覆盖该默认值。实际付费提交仍须具备针对本次任务的明确授权；免协议不等于免授权。

以下用户指令构成目标模式启动：

```text
项目 + 明确集/段 + 要完成的产物/时长 + 自动化范围
```

例如：

```text
示例系列 EP01，15 秒，拆两段，使用已授权模型，全自动。
```

用户明确说“RH 跑 720P 测试 / 提交两个测试 / 生成视频”时，视为对该明确范围的**一次性实际生成授权**；不包含超预算重试、换模型、扩时长、增加候选、发布、删除或覆盖 MASTER。

## 二、Agent 必须自动补齐的内容（不得卡住）

收到目标模式后，Agent 必须连续执行：

1. 运行 Bootstrap，读取项目入口、状态、权威脚本、资产和最近交接。
2. 为本次目标创建唯一 `TASK_CURRENT.md`；不得反过来要求用户先创建任务卡。
3. 从已有权威材料生成 `production_contract.json` **草案**、资产映射和生产单元；故事本任务单仅在用户明确授权后创建。
4. 将旧任务的 FAIL/WAITING 状态与本次目标逐项比对；仅当它是本次镜头的真实依赖时才阻断。不同段、不同任务的历史 FAIL 不得一票否决。
5. 自动执行当前 Gate 内的非付费工作：脚本/镜头核对、资产定位、适用的独立 QA、视频 Prompt、任务包、状态写入。故事本图片默认关闭。
6. **自动补齐缺失的角色/场景/道具 MASTER 候选**：目标模式可按 16 号规则生成候选并独立 QA。关键状态图、故事本单格和拼版不属于目标模式授权；只有用户明确要求或授权当前单元制作时才可生成，并记录 `image_channel` 与成本。
7. 若用户的目标模式指令已经明确授权 RH 测试（或明确说"QA 通过可生视频"），则在合同草案范围内提交一次；**提交前必须落盘确认报告，且参考资产逐个列全、参数齐全**（见 `19_视频提交前确认报告与授权范围规则_v3.0.md`）；未授权时在"待提交任务包"停下。
   **注意**：授权只解决"能不能提交"，不解决"提交得对不对"——参考资产为空或参数缺失时，即使已授权也必须先补齐再提交。

### 2.1 快速路线与确认合并

- 用户明确脚本已确认并授权目标模式时，G1/G2 作为一个交付包一次完成：秒表节拍、镜头表、连续性、生产单元、作者自查和一次独立 Reviewer 结论。无剧情、台词、身份或范围冲突时，不逐 Gate 停下来等待用户重复批准。
- 需要改动已确认剧情/台词、锁定资产身份，或超出单元/时长/授权范围时，才暂停并只询问该项决定。仅镜头表达的安全优化可列入候选，不得静默替换用户已锁定的镜头。
- G3 复用路径、角色和 SHA-256 均未变化的资产 QA；只对新增/变化资产复核。关键状态图、角色状态图和故事本图像都不是隐式目标模式授权；用户明确要求某张状态参考图时，仅覆盖该图及当前单元用途。
- G4 默认 `not_applicable`；不创建任务、QA 或阻塞。复杂度通过动作拆解、Prompt 禁止项和视频 QA 处理。
- G5 将 Prompt、参数、成本、资产清单与一次独立生成前 QA 合并交付。用户已明确授权本单元视频生成时，QA PASS 和提交报告完整后直接进入 G6，不再重复索要 Prompt 确认；没有提交授权时生成待提交包。
- 每个 Gate 只保留一个独立 QA 回合；同一候选不得为 A/B/C 多等级重复审查。只有实质变更才开新版本并重选 QA 深度。

### 2.2 时效性与停滞

简单 5 秒单元的参考主动处理时间：G1+G2 7 分钟、未变资产的 G3 3 分钟、G5（含对应模型 Prompt Skill 与生成前 QA）7 分钟。图像/视频生成、上传、供应商排队和下载单独计时，不纳入上述目标。完成事件使用现有 `at` 与 `elapsed_seconds`；等待原因写入 `pending_decision`。10 分钟无新事件且索引也未更新时，在 `pending_decision` 标明 `疑似停滞 STALLED`、最后有效产物、阻塞原因和继续动作（不改变索引 `status` 枚举）。超过目标时间时保留已有产物继续可做步骤，不得无证据重跑或退回起点。

**禁止把“缺合同、缺任务卡、资产映射尚未写入、旧段 FAIL”表述为“自动化不可实现”。这些是 Agent 自动建卡和解析上下文的职责。**

## 三、用户决定卡与目标模式边界（协议 3.4）

目标模式只减少重复确认，不允许 Agent 替用户作实质创作决定。所有暂停与恢复按 `22_用户决策交互与版本防循环规则_v3.0.md` 执行：在当前对话提出含选项的具体问题；单纯状态字段不构成交接。对已批准的同一版本与范围不重复提问。无回复时保持当前 RUN、版本、已用额度和审批状态，不通过新 RUN、换稿或重复 QA 继续。

## 三、真正需要暂停的条件

只允许在下列情况进入 `EXCEPTION_QUEUE`：

- 无法定位当前权威脚本，且用户指令无法确定剧情；
- 人物/场景/道具 MASTER 不存在，且**自动生成 + QA 连续 2 次仍不通过**（第 2 节第 6 条：缺资产本身不是暂停条件，先自动补齐）；
- 需要改剧情、替换角色、改变美术方向、换模型、超出用户明示的时长/候选/授权范围；
- QA 出现 FAIL / UNCERTAIN；
- 用户没有明确实际生成授权，或需要追加预算/重试；
- 云端任务状态未知。

故事本授权与降级统一见 `核心自动化生产包/03_生产与资产规则_v3.0.md`；Gate 跳过条件见 `核心自动化生产包/02_任务路由与Gate_v3.0.md`。目标模式只触发自动建卡和约定范围内的连续执行，不会自行启用故事本。尾帧按 03 号的独立授权规则处理。

## 四、禁止的错误行为

- 禁止只输出 `READY_FOR_CONTEXT_REVIEW` 然后等待“继续”。
- 禁止把 Bootstrap 当作工作完成。
- 禁止让用户手写 TASK_CURRENT、合同、资产映射等机器生产文件。
- 禁止以历史 A 段 FAIL 阻断无依赖的 B 段新任务。
- 禁止把目标模式理解成越过真实资产、QA 和付费范围的无限授权。

## 五、回复格式

任务启动后先用一行报告：

```text
目标模式已接管：正在自动建卡→锁权威输入→镜头与资产→独立QA→视频Prompt→[已授权则提交 / 未授权则待提交包]。故事本图像默认关闭，仅用户明确授权时启用。
```

随后持续执行，不把每一项中间文件抛回给用户确认；仅在“真正需要暂停的条件”命中时，附证据和唯一需要决定项。

## 五、运行轨迹落盘（用户裁定 2026-09-20）

- 每推进一个步骤，**必须向当前段落的轨迹文件追加事件**：步骤名、Skill、这一步读过的协议文件、证据路径、结果。**缺记录 = 该步未完成。**
- 每段结束、暂停或切换时更新项目索引，并把 `active_run_id` 指向正在做的段；用户刷新总表即可看到“进行到哪一段”。
- 一集 20 段 = `workflow/runs/` 下 20 个段落文件 + `workflow/run_index.json` 一份索引；不得把轨迹写到项目外，不得为清理而删除既有段落文件。
