# 生产与资产规则

> 协议版本：3.0 ｜ 最后更新：2026-09-20

## 每个镜头必须明确

镜头目标、视觉主体、人物身份引用、场景/道具引用、动作边界、起始状态、结束状态、景别/机位、台词/声音、连续性依赖、禁止项、模型参数。

标准化的是字段接口，不是把所有镜头套成同一段 Prompt。模型适配层只能改写表达，不能改人物、动作、时长、台词和禁项。

## 一图一职责

- 角色 MASTER：脸、发、服装、身材、身份。
- 场景 MASTER：空间结构、材质、灯光、固定陈设。
- 道具 MASTER：结构、尺寸、颜色和物体状态。
- 真实成片尾帧：下一镜起始动作、空间、道具位置和屏幕方向。
- 故事本：镜头顺序、调度和动作因果，不锁最终人物身份或视频像素。

## 首尾帧与故事本：默认关闭 + 明确授权

故事本图片、关键状态图和故事本拼版默认关闭。只有用户明确要求“制作故事本”“生成关键状态图”或明确授权某个生产单元使用故事本时，才可制作。目标模式、高风险动作、多人打斗均不构成授权。真实尾帧也须遵循单独的授权开关。

- **授权开关**（写入 `production_contract.json` 的 `authorization`）：
  - `allow_tail_frame_generation`：授权后，生产线才为连续镜头制作真实尾帧；
  - `allow_storyboard_generation`：仅对应用户明确授权的生产单元；不得由风险等级或目标模式自动设为 true。
- **未授权或缺位时的降级**（不停机）：
  - 缺真实尾帧：以合同中已确认的 `start_state` 文字描述 + 上一镜 QA 通过版的记录继续；QA 阶段相应加严起始状态检查；
  - 未授权故事本：合同记录 `storyboard_mode: disabled_by_default`，S07 标记 `not_applicable`；以镜头拆解、动作分段、强化 Prompt 禁止项和更严格的视频 QA 继续。L0/L1/L2 只表示风险和 QA 深度；
  - 直接生产 QA FAIL 时，报告失败证据并询问用户是否授权故事本，不得自动生成或重试。
- **角色/场景/道具 MASTER 是身份权威，不得用相似素材替代**：常规模式下缺 MASTER 停在 G3 请示；**全自动目标模式下按 16 号的授权模型自动补齐——立即生成候选（GPT-Image-2）→ 独立 QA → PASS 后进入下游**，不逐次请示。降级策略不适用于身份权威缺失，但"自动补生成 + QA"适用于目标模式。

## 提交视频时的参考资产（2026-09-20 事故后加严）

**授权通过 ≠ 内容正确。** 用户批准生成视频后，Agent 仍必须在提交前把实际要带的资产与参数列进确认报告：

- **参考资产必须逐个列全**（人物 MASTER、场景 MASTER、道具 MASTER、上一真实尾帧、故事本总图等），每项写明 `path` / `role` / `qa_status` / `sha256`，并确认文件真实存在。
- **零参考资产提交直接阻断**：该带资产却没带，产出必然与 MASTER 不一致，属于不可用产出 + 成本浪费。
- 参数（模型与版本、平台、API 方式、时长、分辨率、帧率、比例、提示词）必须齐全。
- 详见 `19_视频提交前确认报告与授权范围规则_v3.0.md`。

连续镜头在用户授权制作尾帧的前提下，必须使用上一真实成片最后有效帧；每镜写明人物数、左右位置、朝向、视线、道具数、接触状态和结束状态。

## 镜头与动作

每镜只承担一个视觉因果：谁在何处、为何行动、造成什么新状态。高风险动作按“起势 → 接触/受阻 → 结果”拆分。每 3–5 秒至少有一次信息、行动、关系、空间、风险或目标变化。

钩子优先出现在 0–3 秒；节拍链为：钩子 → 目标 → 阻碍 → 行动 → 结果/反转 → 未解决问题。\n
