# 核心总则

> 协议版本：3.0 ｜ 最后更新：2026-09-20

## 权威优先级

用户最新明确裁定 > 当前项目已确认脚本与 `workflow/project_state.json` > 角色/场景/道具 MASTER > 上一真实成片尾帧 > 已确认故事本 > 历史版本。

冲突时低层级不能覆盖高层级。不能凭聊天记忆或旧版本继续生产。

## 自动化必须先做的事

收到“项目 + 集/段 + 产物/时长 + 自动化范围”后：

1. 定位项目根目录、`00_项目入口.md`、状态文件、权威脚本和资产索引。
2. 自动创建唯一 `TASK_CURRENT.md`、`production_contract.json` 草案、资产映射和生产单元，不要求用户手写机器文件。
3. 判断当前 Gate、风险等级和唯一阻断项。
4. 连续执行当前 Gate 内的非付费工作，并把状态、证据和下一步落盘。

## 授权边界

脚本通过不等于生图；故事本通过不等于视频提交；视频通过不等于发布。提交付费任务、重试、换模型、超出时长/候选、发布、删除文件或覆盖 MASTER，都必须有对应的明确授权。**例外：全自动目标模式下，启动指令即一次性授权"流程内补齐缺失资产所需的生图"（GPT-Image-2，含额度耗尽后的 RH 兜底），缺 MASTER 时立即生成 + QA 并继续；生图产物仍须独立 QA PASS 与 `image_channel` 成本留证。**

## 不可越过的硬线

- 不用相似人物/场景图冒充 MASTER。
- 不用故事本、多人合照或视频截图锁人物身份。
- 不用概念图、QA 联系表或文字描述替代真实尾帧。
- 不覆盖原稿、通过版、MASTER 或未指定原片。
- 不把 Bootstrap、建卡或生成 Prompt 说成视频已完成。
- 云端任务状态未知时续查原任务，禁止盲目重复扣费。\n
