## 3.0 相对 2.x 的关键变化

1. **首尾帧与故事本改为授权制增强项**：未获用户授权制作时不阻断生产——缺尾帧按已确认 `start_state` 文字承接，缺故事本按强化禁项直拍继续，并记录降级；仅当降级单元 QA FAIL 才报"建议授权制作"。
2. **生图模型写死 GPT-Image-2**：本机订阅额度通道（Hermes/Codex Agent 调 GPT 前台）优先；RunningHub GPT-Image-2 工作流仅在额度耗尽且用户授权后兜底；`seedream` / `banana` / `qwen-image` 等**全部停用**，不设场景类例外。
3. ~~**生图授权随模式区分**（2026-09-20 晚修订）：全自动目标模式自动补齐 MASTER / 关键帧 / 故事本。~~ **已被 2026-09-29 当前解释取代**：目标模式只处理协议明确授权范围内的身份 MASTER；故事本图片、关键状态图、单格图和拼版必须由用户明确授权当前单元后才启用。见本文件顶部与唯一入口。
4. **协议读取与调用可校验**：开工前须提交协议读取证明（指纹 + 哈希 + 挑战问答）；运行中每一步必须记录 `skill_id` / `protocol_refs` / `evidence`，否则不算完成。
5. **结构清理**：原两个 00 入口（`00_总入口_所有Agent先读.md` 与 `00_自动化生产唯一入口.md`）合并为一个；原 `13_故事本图片与视频生成参考资产选择准则.md` 重编号为 `17_…` 消除与 `13_模型执行前硬门禁.md` 的编号冲突；核心目录内嵌的 `_非核心归档/` 移出至外层归档目录。
6. **文件名统一加 `_v3.0` 后缀**（规则文档与核心自动化生产包）。
7. **保持不变**：付费视频提交一次授权、不自动重试、不换模型、不发布；不使用相似图替代 MASTER。**MASTER 缺失在目标模式下改为自动补齐（生成+QA），常规模式仍停在 G3。**
- **视频提交前必须有确认报告（2026-09-20 事故后加严）**：任何平台、任何方式（含网页手点）提交视频前，必须落盘 `workflow/submission_reports/<unit_id>_<Vn>.json`，列全平台、API 方式、模型与版本、时长/分辨率/比例、**逐个参考资产（path/role/qa_status/sha256）**、提示词、成本、授权来源与用户确认。**授权通过 ≠ 内容正确**：参考资产清单为空或参数缺失时一律阻断（`BLOCKED_INCOMPLETE_SUBMISSION`），即使已获用户授权。自动化目标模式不豁免留档。详见 `19_视频提交前确认报告与授权范围规则_v3.0.md`。

## 3.1 通道安全修订（2026-09-21）

1. RunningHub视频通道分级：会员 `NORMAL→coins` 为默认主通道；个人网页端仅用户指定时使用；企业 `SHARED→cash` 仅用户明确授权后使用，Agent不得自行切换。
2. G6提交报告新增 `channel_class` 与 `billing_preflight`；API提交前必须核验 `api_type` 及 coins/cash 前后余额。
3. 删除泛化路由 `RUNNINGHUB_API_H3`，改为 `RUNNINGHUB_PERSONAL_H3` 与 `RUNNINGHUB_MEMBER_API_H3`；通道不明直接阻断。

## 3.2 生产提速修订（2026-09-29）

1. 目标模式且脚本已确认时合并 G1/G2，一次产出节拍、镜头、生产单元和独立复核；仅真实内容/身份/授权冲突暂停。
2. G3 按资产路径、角色与哈希复用 QA，只复核变化项；G4 默认跳过；G5 合并 Prompt、参数、成本、资产清单与一次生成前 QA。
3. 同 RUN 同协议指纹复用通用读取证明；记录步骤耗时和等待原因，超过 10 分钟无事件标记 `STALLED`。
4. 不削弱剧情确认、独立 QA、付费授权、参考资产完整性或真实成片 QA。
5. 单条视频目标时长 ≤5 秒默认免本地生产协议，走对话推理；用户明确要求时再启用 RUN/Gate/留痕，付费授权边界保留。

## 3.3 七 Gate 流程重整（2026-09-29）

1. 主流程统一为 G1–G7；项目接入并入 G1，G5.1 并入 G5，G6.1/G6.2 并为 G6 内部检查，原 G8 从本地生产 Gate 移除。
2. G5 必须先确认本次视频模型，并调用该模型对应的 Prompt 写作 Skill；未运行或无证据不得放行。
3. G7 常规工作为查到任务终态、报告进度并下载成片到本地；成片内容 QA 仅用户明确要求模型/Agent 分析时执行。
4. 旧 RUN、合同与轨迹不回写；继续既有 RUN 时保留历史事实，并按需映射到当前 Gate 语义。

本次规则对新请求生效；不回写既有 RUN、任务合同或历史轨迹。旧 RUN 的协议证明仍绑定创建时的 manifest 指纹；如继续并要求按新协议验收，须重新证明当前 Gate，不得伪造或改写旧证明。

## 3.5 六 Gate 与十二步生产终点（2026-10-10）

1. 新 RUN 使用 G0 接入/恢复 + G1–G6；G0 不新增审批门禁。
2. 注册表的十二个用户展示步骤为 G0-S01 至 G6-S12；G6-S10 是三平台适配器按 RUN 选一，G6-S11 授权提交并留 Task ID，G6-S12 查询原 Task ID 至供应商终态、记录结果链接并报告后结束 RUN。
3. 新 RUN 不自动下载视频、不做文件下载检查、不做成片 QA；用户后续请求时另建任务。生成前 QA、资产身份、授权、预算、资产绑定及幂等门禁保留。
4. 历史 RUN/事件的 G0–G8 与旧 S 编号不改写，按其创建时注册表解释；新旧编号映射仅用于显示和迁移。
5. 本地步骤、Gate、QA 角色与事件类型配置统一从 `skills/skill-chain.json` 派生；目标裁剪及哈希防重复规则以执行合同和校验器实现为准。

## 升版与维护规则

- 任何核心协议文件的增删改，**必须重跑** `python tools/protocol_fingerprint.py generate` 重新生成 `protocol_manifest.json`；否则所有人的协议读取证明都会 REJECTED（刻意设计，防止协议被改动后仍用旧证明开工）。
- 新增规则文档按下一个可用编号命名，并加 `_v3.0`；次版本升级（3.1）只改 `VERSION.md` 与本段记录，不改文件名。
- 引用协议文件时**必须写完整文件名含 `_v3.0`**，避免与归档版本混淆。
