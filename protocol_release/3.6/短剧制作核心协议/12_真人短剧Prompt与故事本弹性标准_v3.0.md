# 真人短剧 AIGC：Prompt 与故事本的弹性标准｜V1

> 协议版本：3.0 ｜ 最后更新：2026-09-20

## 一、标准化 Prompt 到底标准什么

真人短剧不确定性高，不能把 Prompt 标准化成固定句式或固定画面。真正应该标准化的是**可执行接口**：

```text
镜头目标
视觉主体
人物身份引用
场景/道具引用
动作边界
起始状态
结束状态
镜头语言
台词/声音
连续性依赖
禁止事项
模型参数
```

每个镜头根据内容填写必要字段。没有用到的字段不强行添加。Prompt 编译器或 Agent 负责把这些字段翻译成适合 H3、Seedance 或其他模型的自然语言，不得反过来让模板改剧情。

## 二、真人短剧的 Prompt 应该分三层

### 1. 不变层（Series / Project Contract）

只写跨镜头稳定的内容：人物身份、服装基准、世界观美术、画幅、画质、禁用元素、角色关系。不要把具体动作和镜头塞进这里。

### 2. 镜头层（Shot Brief）

只写当前镜头真正需要的内容：谁、在哪里、要完成什么动作、动作结果、景别、机位、时长、台词。每镜不同，不追求文字长度一致。

### 3. 模型层（Model Adapter）

把同一个 Shot Brief 翻译成 H3 / Seedance 能理解的提示词。模型适配层可以改变措辞、顺序和强调方式，但不能改变人物、动作目标、时长、台词和禁项。

因此，所谓“标准化 Prompt”是：

```text
同一套字段接口 + 不同镜头内容 + 不同模型翻译器
```

不是：

```text
所有镜头套同一个 Prompt 模板
```

## 三、故事本输入

图片生成权限、G4/S07 路由和未授权降级以 `核心自动化生产包/03_生产与资产规则_v3.0.md` 为唯一规则来源。编写 Prompt 时，简单镜头直接使用 Shot Brief；缺少故事本不得阻断 Prompt。只有合同记录当前生产单元的明确授权后，才能按 `key_state_only` 或 `full_storyboard` 使用对应图像。

## 四、什么情况下才拆成多个视频生产单元

不是看到多个动词就机械拆分。只有当下列因素改变时才优先拆：

- 视觉主体改变；
- 空间改变；
- 服装/人物状态改变；
- 动作接触风险高；
- 镜头目的改变；
- 说话人改变且口型需要独立控制；
- 关键道具状态改变；
- 当前模型在一个单元内无法稳定完成动作链。

如果同一主体、同一空间、同一状态下的动作能够在 5–8 秒内稳定完成，可以合并，不必为了形式拆碎。

## 五、以 15 秒两段任务为例

原来的 A1–A4 是**镜头逻辑拆解**，不是强制要求生成 4 条视频，也不是强制制作 4 份完整故事本：

```text
A1：抵达
A2：接触
A3：锁入
A4：针与台词落点
```

更合理的执行方式是先判断：

- A1+A2 是否能在同一视频单元中稳定完成；
- A3+A4 是否有明确状态承接；
- 取心针悬停和台词是否需要独立口型控制。

可能的最终生产单元是：

```text
视频单元 V1：A1+A2，8 秒
视频单元 V2：A3+A4，7 秒
```

也可能因模型测试结果拆成 3 或 4 个单元。**镜头拆解数量 ≠ 视频提交数量 ≠ 故事本张数。**

## 六、自动化的正确目标

自动化按用户授权与风险选择最低必要成本的生产路径；风险只决定镜头拆解和 QA 深度，不打开故事本图片生成：

```text
低风险：Shot Brief → 直接生成
中风险：Shot Brief → 加强动作连续性 QA → 生成
高风险：镜头表/ACT 动作分段 → 强化 Prompt 禁止项 → 加强视频 QA → 生成
```

自动化 QA 也应先判断风险等级，再决定检查深度。不能因为协议要求严格，就把所有真人短剧都升级成最高规格流程。\n
