# Running the production control console

## Start from the repository root

Use the repository's documented launcher or run the local validation commands below. Configure `SHORT_DRAMA_PROTOCOL_ROOT` only when a separate local authority folder should override the bundled release.

```powershell
py -3 -m production_control.contract_validator examples/production_contract.valid.json
py -3 -m production_control.prompt_linter examples/prompt_unit.direct.json
py -3 -m production_control.pipeline_validator examples/pipeline_bundle.valid.json
py -3 -m production_control.preflight_gate examples/preflight.valid.json
py -3 -m production_control.skill_chain_validator
py -3 tools/validate_asset_index.py examples/asset_index.example.json
py -3 -m production_control.protocol_fingerprint check --root 'protocol_release/3.6/短剧制作核心协议'
py -3 -m pytest -q
```

## Start and resume a RUN

Provide an existing episode project root and a unique RUN ID. Inspect a resume first; resume updates the original RUN, carries its evidence and accounting forward, and does not resubmit an existing provider task.

```powershell
py -3 tools/start_run.py '<PROJECT_ROOT>' --help
py -3 tools/resume_run.py '<PROJECT_ROOT>' --run '<RUN-ID>' --inspect
py -3 tools/resume_run.py '<PROJECT_ROOT>' --run '<RUN-ID>'
```

For a RUN with an existing provider Task ID, continuation routes to G6-S12 status lookup. Unknown or unverifiable provider state is reported as an exception and is never called success.

## Read the run report and asset index

```powershell
py -3 -m production_control.run_report '<RUN_STATE_FILE>' --html '<REPORT_FILE>'
py -3 tools/validate_asset_index.py '<SERIES_ROOT>/资产库/asset_index.json'
```

Store authoritative scripts, assets and media in the project folders. The series-level asset index stores metadata and references; it does not replace the source files. Confirmed RUN inputs may be snapshotted under that RUN's workflow directory.

## Authorization boundary

Offline validators do not contact a provider and do not prove a live production run. Provider submission requires a current, explicit authorization and is not performed by the examples above. G6-S12 reports status for an existing Task ID and does not resubmit it. Download, editing and post-generation analysis happen only as separate requested tasks.
