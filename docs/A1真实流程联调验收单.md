# A1 真实流程联调验收单（交给生产 Agent）

本单只规定协议和看板的联调验收，不授权制作、提交、付费或发布。生产 Agent 必须先读取项目最新任务卡、生产合同、用户裁定和核心协议原文；本单不能覆盖它们。

## 当前版本核对

- A1 已确认做 15 秒四段减法；生产 Agent 先核对项目内最新 V7.1 裁定与用户确认，不能把旧 13 秒或 V6 的 Gate PASS 当成本版 PASS。
- G1 核对脚本与四段结构；G2 核对时间、动作、对白与连续性；G3 核对资产角色和当前版本；G4 核对故事本；G5 核对 Prompt、Skill 审计和独立 QA；G6 核对合同授权、平台/项目绑定、实际资产回读及成本。缺证据即待核验或阻断，不跨 Gate 代签。
- 只有当前合同明确授权且所有前置 Gate 通过，才允许进入平台提交；`qa_only`、`max_submissions=0` 或其他限制仍有效时，不得提交生成。用户确认创意减法不等于付费授权。

## 每一步真实上报

1. 从 `skills/skill-chain.json` 或 `tools/append_event.py --list-steps` 读取 S01–S13、Gate 和必修协议。正式步骤只用稳定 ID。Gate 内检查项不冒充正式步骤，也不增加正式进度。
2. 生产者先留下版本明确、实际存在的证据。GLM 在自己的会话中调用 `tools/append_event.py` 代理写入 `SUBMITTED_FOR_QA`、阻断或待审批；`--actor` 记录实际生产模型，`--writer-model` 声明 GLM。不能事后批量补造事件。
3. GLM 读取原始产物与适用协议，独立审核后才调用 `tools/qa_verdict.py`。调度失败、HTTP 错误、无报告、旧版报告均不算 PASS。生产者不得自己写 `COMPLETED`。
4. 无法归类的真实辅助活动必须明确标记链外并保留原始名字；它可显示，但不能推高 G1–G6 正式进度。历史 18 条不回写、不删除。

## 看板现场验收

由用户双击唯一入口 `tools/一键打开看板.cmd` 启动本机服务，确认打开的实际端口及项目目录。生产 Agent 不在沙箱后台常驻服务。每次上报后核对 RUN 轨迹、`run_index.json`、网页刷新三处是否同步，并记录时间与截图。页面 5 秒刷新不应让用户展开的区块自动收回；若出现，记录复现步骤而不是误判生产停滞。

验收时逐项观察：G1–G6 都可见；当前版本未做、待 QA、失败、待审批与通过不混淆；旧版证据显示需复核；链外活动可追溯但不计进度；G6 的平台上传、`resourceIds`、节点回读和独立 QA 分别核验；切换项目后不串 RUN。

## 必须报告的限制

目前 `--writer-model` / `--qa-actor` 是命令参数，不是密码或签名。CLI 拒绝错误模型名，但不能证明实际操作者身份。联调报告必须注明 GLM 的真实调用会话和证据；未加认证前，不得把“参数校验通过”写成“技术上保证 GPT 无法写入”。

联调结论只写三类：通过（附轨迹、网页和 QA 证据）、失败（附复现）、未验证（缺真实运行或权限）。没有生产 Agent 实跑和浏览器观察前，本单自身不能证明 A1 全流程可用。
