# 短剧生产小改与独立 QA 规则 v1

## 目的与权限

减少无效重复 QA，不牺牲结构安全、人物/道具连续性或真实成片验收。

- 执行模型不得自审、自签 PASS，也不得写看板轨迹。
- 生产模型只交付产物与事实。生产提交和 QA 结论都由路由选出的 GPT QA 模型写入轨迹。
- `actor` 记录实际生产执行模型；QA 事件的 `actor` 和 `writer_model` 都记录 QA 模型。生产提交事件的 `actor` 是生产模型、`writer_model` 是路由 QA 模型。
- 轨迹中的模型名是调用方声明，当前 CLI 无法认证真实模型会话。不得将参数校验说成身份认证；需保存实际 QA 报告及对应会话证据。
- QA 通过仅表示相应证据过审，不授予生图、视频生成、付费、导出或发布权限；授权仍以当前合同和用户明确批准为准。

## 模型路由

| 执行模型 | 独立 QA / 唯一轨迹写入者 |
|---|---|
| `gpt-5.6-luna` | `gpt-5.6-terra` |
| `gpt-5.6-terra` | `gpt-5.6-sol` |
| `gpt-5.6-sol` | `gpt-5.6-luna` |

仅使用 `openai-codex` GPT。禁止 Zai/GLM QA。未登记的执行模型必须拒绝，不能猜路由、回退到同一模型或假报通过。当前可用路线是 Luna 执行、Terra QA。QA 模型负责记录生产提交与 QA 结论；执行模型没有任何轨迹写权限。

## 改动等级

每次修改前先记录任务 ID、受影响文件、当前版本和 QA 等级。稳定候选版本以版本号区分；失败后统一修订并递增版本，旧文件和旧证据保留，不覆盖、不删除。

### A 级：文字/格式快速 QA

标点、错别字、专名大小写、不改含义的压缩、Prompt 说明顺序、表格整理、无生产约束影响的重复解释删除。

- 只读受影响文件及必要上下文；只查矛盾、漏字、禁令冲突和引用错误。
- 不调用 LibTV，不生成图/视频/音频，不改 MASTER、项目状态或生产文件（除非用户明确要求）。
- 每个稳定版本仅一次独立快速 QA，不自动升级完整 QA。
- 快速 QA 180 秒时限；超时结论是 `TIMEOUT`，不标绿、不推进。调度方必须在 180 秒终止等待；当前本地 CLI 只能校验/记录耗时，不能取消 Hermes 正在运行的静态 delegation。

### B 级：局部内容 QA

单镜头动作/景别/机位/运镜、台词/说话人/时长、道具出现或位置、首尾帧绑定、镜头时长/节拍、局部视觉因果调整。

- 只审当前版本受影响镜头和前后相邻镜头。
- 核查动作因果、说话权、时长、人物数量、道具连续性、首尾帧关系。
- 必须读取当前版本文件，不依据聊天记忆；发现影响其他镜头时升为 C 级。
- 同版本的小改先本地合并，再做一次 B 级 QA。

### C 级：完整生产前 QA

更换角色/资产/服装/脸/姿态/身份参考、场景或道具 MASTER、首尾帧、人物数量/关系/站位、核心动作因果、台词含义/说话窗口、模型/画幅/分辨率/时长/付费规格、参考绑定、故事本结构/镜头顺序、结构性失败或用户明确要求重新审计/放行。

- 读取当前版本脚本、分镜、故事本、Prompt、资产合同、首尾帧及项目状态。
- 审 G1–G6 或当前项目对应的全部生产前 Gate；核角色/人数/服装/肢体/鞋/道具/开关/灯光/空间/动作连续性。
- 核台词逐字保留、动作段和声音段一致、说话窗口与唯一说话人、当前锁定 MASTER、模型与生成规格。
- 结论只能为 `PASS`、`FAIL` 或 `CONDITIONAL`；必须给证据路径、版本和具体问题。
- PASS 不代表获准生图、视频生成或付费。

### FINAL：生成后成片 QA

与生产前 QA 分开执行，必须检查真实视频而不是 Prompt 自证：完整播放，抽查首帧/关键动作/尾帧，检查人物、脸、服装、肢体、鞋、道具、开关、灯光、空间、动作是否真实发生、口型/台词/声音同步、黑帧/冻帧/闪烁/变形/断裂。跨段连续性只以真实上一段成片尾帧为权威。自动 QA 不替代用户完整目视审片；生成成功不等于可用。

## QA 调用与复核上限

- 每个稳定候选版本最多一次同等级 QA。QA 失败后先合并全部问题，再统一修订、递增版本并做一次 QA。
- 同一版本对同一 `issue_id` 最多一次针对性复核；不得用它重复跑整份完整 QA。复核需显式 `attempt=2` 且沿用同一 `issue_id`。
- 同一问题的复核只能验证指定问题；发现新问题时停止该轮放行，整理后提升版本/重新定级。
- QA 输入只包含当前版本及所需相邻镜头/证据；不读无关历史线程，不混入已失效旧版。
- 已经用户目视通过的素材，不因自动 QA 的低置信度提示自动重跑；结构性穿帮或真实成片证据问题除外。
- QA 只输出审计，不修改生产文件；只有用户明确要求修订时才修改。

## 看板记录字段

QA 结论必须记录：任务 ID、当前版本、QA 等级、执行模型、QA 模型/写入者、审计证据、耗时、结论、阻塞问题、下一步。`PASS → COMPLETED`；`FAIL → FAILED`；`CONDITIONAL/TIMEOUT → WAITING_APPROVAL`，不得显示绿色通过。

标准人读输出：

```text
【独立 QA】
- 任务ID：
- 当前版本：
- QA等级：A / B / C / FINAL
- 执行模型：
- QA模型：
- 审计范围：
- 结论：PASS / FAIL / CONDITIONAL / TIMEOUT

【通过项】
1.
2.

【失败项或风险】
1. 文件路径 + 版本号：
2. 具体问题：
3. 是否阻塞生成：
4. 修复建议：

【下一步】
- A级通过：继续当前流程，不升级 QA；
- B级通过：仅允许进入对应局部制作；
- C级通过：仍需用户明确批准后才能生成或付费；
- FAIL：先统一修改，再进行一次复核；
- TIMEOUT：停止等待，缩小输入或更换 QA 模型，不得无限重试。
```
