# Task knowledge index implementation strategy

## Current approach

Core rules, active Gates, authorization, asset identity and submission limits are loaded deterministically from versioned registries. Historical lessons are loaded only when relevant to the project, stage or asset.

The first search layer is filenames, keywords and a JSON metadata index. It does not require a vector database or full RAG. Each entry stores a topic, scope, stage, source path, version, effective status, related asset IDs, content hash and review date. The source document remains authoritative.

## Retrieval and invalidation

1. Narrow candidates by project, current stage and asset ID.
2. Exclude retired, unconfirmed and out-of-scope entries.
3. Read the source and check version, dependency hashes and confirmation state.
4. Mark only affected entries stale when their content or dependencies change; never reuse old QA or authorization as new evidence.
5. Record the source paths used so hidden context does not affect production decisions.

Consider vector retrieval only if measured search volume and timing show keyword search is insufficient. Any later index must preserve source paths, version and access filters and must not replace deterministic gates.
