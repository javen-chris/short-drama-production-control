# 本地短剧生产协议与控制台优化｜目标模式提示词

请以目标模式完成本地短剧生产协议、控制台与现有 GitHub 仓库优化。按 P0–P3 逐项实施、验证、记录并报告，不停在计划阶段。

## 工作边界与授权

- 工作根目录：`<WORK_ROOT>`
- 权威协议：`短剧制作核心协议`
- 控制台仓库：`短剧生产线控制台`
- Obsidian 查阅副本：`<OBSIDIAN_SHORT_DRAMA_SECTION>`
- 开始前读取 AGENTS、唯一入口、VERSION、注册表、QA 配置、合同/schema、恢复/提交/查询/指纹/迁移/看板实现，检查 Git 分支、远端、PR 和未提交修改。保留用户修改，不使用 reset、clean 或覆盖权威资产。
- 授权修改协议、控制台、Schema、模板、Skill、示例、测试与文档；维护现有 GitHub 仓库；建立分支、提交本次变更、推送、创建 PR、检查 CI，并在保护规则允许且必需检查通过后合并及同步本地；最后同步 Obsidian 人读副本。
- 不授权付费生成、视频提交、发布、删除生产资产、覆盖 MASTER、改写历史 RUN，或向 GitHub 上传生产素材、真实 RUN、预算/授权/QA 私密证据和密钥。遇到无法裁定的既有修改或远端保护阻止合并，报告原因并继续不依赖该问题的工作；不得绕过保护或强推。

## 固定生产定义

新流程为 G0 接入与恢复 + G1–G6 六个生产阶段，用户展示步骤只到 G6-S12：

| 显示编号 | 工作 |
|---|---|
| G0-S01 | 项目接入、任务路由与原 RUN 创建/恢复；不增加审批门禁 |
| G1-S02 | 权威脚本、确认边界与节拍整理 |
| G2-S03 | 镜头、生产单元、调度与连续性 |
| G2-S04 | 脚本与镜头一次合并独立复核 |
| G3-S05 | 资产映射、身份锁定与最小生成路线 |
| G3-S06 | 缺失身份资产补齐及检查，仅按适用授权 |
| G4-S07 | 故事本/关键状态图，可选；未授权为 not_applicable |
| G5-S08 | 调用匹配模型 Skill 并编译 Prompt |
| G5-S09 | 一次合并生成前独立 QA |
| G6-S10 | 单平台提交前校验与适配 |
| G6-S11 | 授权提交、幂等保护与真实 Task ID 留档 |
| G6-S12 | 查询原 Task ID、进度和供应商终态结果 |

G6-S12 核实成功终态、记录输出链接并报告后结束 RUN；失败不自动重试；状态不明时记录异常。没有 G7/G8、自动下载、下载文件检查或默认成片 QA。后续下载、剪辑或成片分析只在用户单独要求时另建任务。显示编号、内部步骤 ID、Skill 身份分开；历史 RUN 按原注册表解释，不改写。

## P0：统一规则并消除循环

1. 统一入口、执行细则、Gate、注册表、合同、Schema、模板、看板与 QA 路由；活动配置仅启用上述十二步。
2. protocol_refs 按任务、阶段和平台裁剪。RunningHub 专用规则只进入 RunningHub 合同；Prompt-only、小云雀、LibTV 不读取无关内容。核心规则确定性读取。
3. 将生产事实、独立内容 QA、执行器调用证据分开。模型名只是路由声明；客户端启动/会话/完成记录不得称为服务端身份认证。
4. 区分权威 MASTER 源文件、系列/单集索引、RUN 不可变输入快照、故事本、真实尾帧、候选和失败图。快照不成为 MASTER，不覆盖源文件。
5. 统一等待、恢复和终态；用户等待时禁止重复 QA 或推进依赖步骤；供应商排队不算 Agent 停滞；重建/迁移不得清空历史、预算、授权、QA 或提交次数。
6. 以输入/产物哈希、审查范围和 issue_id 去重。一次完整 QA；轻微修正后最多一次针对相同问题复核。同哈希不能改版本名或 QA 等级重做完整审查；实质变更须对应授权。

## P1：按请求裁剪、按证据恢复

1. 提供显式原 RUN 恢复命令。读取合同、事件、产物、证明、用户等待状态和供应商 Task ID；自动找出第一个缺失或失效步骤，不创建替代 RUN。
2. 复用必须核对证据哈希、依赖输入、模型参数、适用协议、QA 路由和任务身份。历史没有哈希时标记为无法自动证明，不虚构有效性。跨 RUN 仅可复用满足全部条件的内容产物及证明，不继承授权、预算、Task ID 或提交次数。
3. 已有 Task ID 只查询原任务，不重复提交。脚本已确认的目标模式合并 G1/G2；G3 只检查变化资产；未授权 G4 跳过；G5 合并 Prompt、参数、成本、资产与一次生成前 QA。Prompt-only 在 G5 结束，视频任务进入 G6。
4. 当前阶段清单列明必读文件、有效证明、复用结果、缺失项、阻断原因、责任方与下一动作。看板明确区分复用、跳过、等待、异常、已提交、供应商终态和 QA 结果。

## P2：资产组织与索引

采用系列库 + 单集项目：系列根放人物/场景/道具可复用 MASTER、`asset_index.json` 与系列入口；每集保留项目入口、脚本、design、场景/物品资产、故事本与首尾帧、Prompt、视频、workflow、iterations 和归档。workflow 可含 `project_state.json`、RUN 轨迹、`asset_snapshots/<RUN-ID>/`、提交包、QA 报告和回执。

索引记录稳定 asset_id、对象与职责、人物形态/服装、版本、确认状态、权威源路径、SHA-256、参考职责、确认依据和追加式变更记录。选择资产按 ID/职责/哈希，不按文件名或视觉相似度猜测。已有项目声明真实路径，不批量搬迁。

快照仅保存用户确认用于当前 RUN 的输入。缺失时仅在声明的项目/资产根按完整 SHA-256 精确查找；多副本确定性选择并记录，复制前后核验；不扫描全盘、不使用相似替代、不覆盖损坏快照。

## P3：最终包、协议迁移、耗时与仓库

1. 保留最终请求→上传绑定→同包独立 QA→同包提交；审查对象采用解析后 JSON 的规范哈希，图片按原始字节哈希。排版变化不使 QA 失效；内容、参数、绑定、资产或适用规则变化使相关 QA 失效。
2. 保留真实 webappId/workflowId 字段；提交原冻结 payload，不重新取模板或拼接节点。网络前落单次意图；超时保留消费次数且不自动重试。
3. 协议维护保存文本版本和 manifest。迁移先列差异与当前/后续/无关影响，再依据已有用户确认记录处理；缺失旧文本标 UNKNOWN。按影响范围复核，不令无关 RUN 全部失效。
4. 分开记录资料读取、生产、QA、用户等待、上传、供应商排队与下载耗时；统计重复读取、重复审核、停滞和 RUN 重建。只读比较真实历史正常与循环 RUN；数据不足时不编造提速比例。
5. 不建设完整 RAG 或向量库。核心规则确定性读取；其余资料按项目、阶段、模型、资产 ID 加载；历史经验先用关键词和元数据索引。
6. GitHub 使用版本化、去敏协议发行副本和可配置/相对根路径。README、安装/启动/维护命令、目录、依赖、Schema、示例、测试和 CI 必须在没有本机 D 盘、密钥和生产素材时运行。CI 验证合同、Schema、注册表、协议 manifest/链接、资产索引、测试与安全扫描。
7. 只提交本次明确归属的代码/文档。创建独立分支与 PR，记录行为变化、历史兼容、检查结果和未验证范围；等 CI 与必要审查通过后按仓库规则合并，核实远端提交并安全同步本地。

## 验收与交付

验证：已确认脚本+现有资产+未授权故事本可到生成前就绪；Prompt-only 在 G5 结束；原 RUN 按有效证据恢复；已有 Task ID 只进 G6-S12 查询；成功链接结束 RUN；供应商失败、下载/QA 失败、用户等待和未知结果不会误报完成；相同产物不重复完整 QA；快照在源文件变化后仍可验证；最终包排版/内容/图片哈希行为正确；平台协议裁剪正确；协议迁移保留历史和计数；旧编号语义不变；GitHub CI 不依赖私人路径或密钥。

最后重算并核验本机权威 manifest 与仓库发行副本，说明其覆盖文件；同步 Obsidian 的人读摘要与本提示词。交付逐项状态、文件清单、真实检查输出、未验证部分、可用启动/恢复/资产索引/指纹命令、仓库/PR/合并提交链接和本地同步状态。离线替身不称为真实平台端到端通过。\n
